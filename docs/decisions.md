# สรุปการตัดสินใจออกแบบ

สรุปผลการออกแบบระบบ Adaptive Tutor ณ วันที่ 24 ต.ค. 2569 เรียงตาม 7 หัวข้อของการนำเสนอ คำศัพท์ทุกคำนิยามไว้ใน [CONTEXT.md](../CONTEXT.md) ผังการทำงานอยู่ใน [flow.md](flow.md) และการตัดสินใจที่เปลี่ยนทีหลังได้ยากอยู่ใน [adr/](adr/)

## ขอบเขตและเทคโนโลยี

- ทำงานบน localhost เป็นหลัก ต้องใช้อินเทอร์เน็ตเพื่อสร้างและสอนด้วย Gem (ยกเลิกข้อกำหนดออฟไลน์เมื่อ 25 ต.ค. 2569)
- Backend เป็น Python FastAPI เซิร์ฟเวอร์เดียว ทำทั้ง REST, WebSocket (ข้อมูลสดฝั่ง Teacher และ Admin) และเสิร์ฟหน้าเว็บ เก็บข้อมูลใน SQLite
- Frontend เป็น React + Vite วันสาธิตให้ FastAPI เสิร์ฟไฟล์ที่ build แล้ว
- ลำดับชั้นเนื้อหาคือ Subject → Question Set → Item ส่วน Knowledge Map เป็นของ Subject และไม่มีชั้น Module
- ครูสร้างบทเรียนเป็น Gem แบบ Gemini Gem แล้ว AI สร้างเนื้อหาทั้งหมดให้ ดูหัวข้อ "Gem" ด้านล่างและ [ADR-0003](adr/0003-gems-ai-builds-lessons-rules-still-grade.md)
- ไม่มีวิชาตัวอย่างติดมากับระบบแล้ว (เอาชุด "แก้สมการสองขั้น" ที่เขียนด้วยมือและข้อมูลการเรียนของระบบเก่าออกเมื่อ 25 ต.ค. 2569) บทเรียนทุกชุดเป็น Gem ที่ครูสร้าง
- การสาธิตหัวข้อ 2–6 และนักเรียนจำลองทำงานบน "Gem ที่ใช้สาธิต" ที่ Admin เลือกในหน้า Gem ที่ครูออกแบบ (ถ้ายังไม่เลือกใช้ Gem แรกที่สร้างเสร็จ)
- repo นี้เป็นสาธารณะ ห้าม commit API key ข้อมูลนักเรียน หรือเอกสารบทเรียนของอาจารย์

## Gem (ออกแบบใหม่ 25 ต.ค. 2569)

ครูสร้างบทเรียนแบบ Gemini Gem ส่วน engine ปรับตัวยังทำงานเหมือนเดิม ([ADR-0003](adr/0003-gems-ai-builds-lessons-rules-still-grade.md))

**หน้าสร้าง Gem ของครู** (หน้าตาแบบ Gemini)
- ชื่อ, คำอธิบาย, Gem Instructions พร้อมปุ่มให้ AI เกลาคำสั่ง, Starter Tools และ Knowledge File (PDF, txt, md แยกต่อ Gem ไม่มีช่องปิดการอ้างอิง)
- Starter Tools มีสองส่วน: สวิตช์เครื่องมือการสอน (แชต, บันไดคำใบ้, Isomorphic Test, Walkthrough, ทบทวนพื้นฐาน) และ Starter Prompt ที่นักเรียนกดถามได้
- ครูแก้ได้เฉพาะ Role & Persona และเพิ่มกฎของตัวเอง ส่วน Constraints & Fallback ล็อกไว้และแสดงแบบอ่านอย่างเดียว
- พรีวิวด้านขวาให้ครูลองเรียนผ่าน engine จริงด้วยนักเรียนทดสอบ ไม่นับเข้าสถิติห้อง และแสดง prompt 4 กรอบที่ส่งไปจริง
- ค่าพารามิเตอร์ของ engine เป็นค่าระดับระบบที่ Admin ปรับ ยกเว้นตัวเลขที่ครูเขียนในคำสั่งของ Gem ซึ่ง Gem Flow ใช้ได้ภายในช่วงที่ปลอดภัย (ดูหัวข้อ Gem Flow)

**Item Bank**
- กดบันทึกแล้ว LLM สร้าง Knowledge Map, โจทย์หลัก 8–12 ข้อคละความยาก, Prerequisite 2–3 เรื่องเรื่องละ 3 ข้อ, ข้อคู่ขนาน 1 ข้อต่อโจทย์หลัก, คำใบ้ 3 ระดับ และ Bug Library ขนาดคลังปรับได้ในหน้า Admin
- ทุกข้อมี Answer Key แบบมีโครงสร้าง engine ตรวจด้วยกฎ LLM ไม่ตัดสินถูกผิด
- Answer Key Check สองชั้น: LLM แก้โจทย์ซ้ำโดยไม่เห็นเฉลย และ sympy คำนวณเฉลยจริงสำหรับสมการและเลขคณิต ข้อที่ไม่ผ่านเป็น Flagged Item ซ่อนจากนักเรียนจนครูยืนยัน
- แท็บคลังโจทย์ในหน้า Gem ให้ครูตรวจ อนุมัติ แก้ เพิ่มเอง และลบโจทย์ทีละข้อ ข้อที่ครูบันทึกถือว่าครูตรวจแล้ว (ครูเป็นผู้ตัดสินสุดท้าย แม้ sympy จะเตือน)
- สถานะของโจทย์: ใช้งานอยู่ · เฉลยติดธง (ซ่อน) · รอครูอนุมัติ (AI สร้างจากปุ่ม "สร้างเพิ่ม" ซ่อนจนครูอนุมัติ) · สร้างสดรอตรวจ (นักเรียนใช้ได้ทันที ครูตรวจย้อนหลัง) หน้าภาพรวมของครูเตือนเมื่อมีข้อรอตรวจ
- แผนผังความรู้และ Bug Library แก้ได้ในหน้าแก้คลังโจทย์แบบเดิม (ปุ่ม "แก้คลังโจทย์")
- Live Generation: ระหว่างเรียน เมื่อคลังใกล้หมดหรือต้องการข้อคู่ขนานเพิ่ม สร้างสดได้ไม่เกิน 10 ข้อต่อนักเรียนต่อ Session
- ชุด "แก้สมการสองขั้น" เดิมแปลงเป็น Gem ตัวหนึ่ง

**การอ่าน Knowledge File (ปรับ 25 ต.ค. 2569)**
- ตอนสร้างคลังโจทย์ AI อ่านต้นฉบับเต็มทุกไฟล์ได้ถึง 600,000 ตัวอักษรเมื่อใช้ Gemini (300,000 เมื่อใช้ Claude, เดิมอ่านแค่ 12,000 ตัวอักษรแรก) ยาวกว่านั้นให้ AI สรุปทีละส่วน 100,000 ตัวอักษร (สูงสุด 20 ส่วน) โดยคัดลอกโจทย์ เฉลย ตาราง และแนวทางคำใบ้ของครูตรงตัว แล้วใช้บันทึกทั้งหมดแทน หน้าสร้าง Gem บอกว่าอ่านครอบคลุมกี่เปอร์เซ็นต์ สิ่งที่อ่านได้เก็บไว้ใช้ตอนสร้างโจทย์สดด้วย
- ขั้น "จำ" ก่อนสร้างโจทย์: AI อ่านเอกสารทั้งหมดแล้วจดสาระ มโนทัศน์และกฎ โจทย์ที่ครูเขียนไว้ (คัดลอกตรงตัว) ข้อผิดพลาด และแนวทางการสอน พร้อมระบุว่ามาจากส่วนไหนของเอกสาร บันทึกนี้ใช้เป็นรายการตรวจตอนสร้างโจทย์ และครูเปิดดูได้ที่แท็บคลังโจทย์ ("AI จำอะไรจากเอกสารก่อนสร้างโจทย์")
- โจทย์ทุกข้อต้องระบุส่วนของเอกสารที่ใช้สร้าง (แสดงในแท็บคลังโจทย์) หน้า Gem บอกว่ากี่ข้อมีแหล่งอ้างอิง
- ตอนอัปโหลด Gemini อ่านไฟล์เอง: PDF (รวมภาพสแกน) ทีละ 6 หน้าพร้อมกัน และรูปภาพ ถอดเป็นข้อความครบทุกบรรทัด รักษาตารางและสมการ หน้าที่ Gemini อ่านไม่สำเร็จใช้ตัวอ่านในเครื่องแทนเฉพาะหน้านั้น ไม่มี key หรือ Offline Mode ใช้ตัวอ่านในเครื่องทั้งไฟล์ (ตัวอ่านในเครื่องทำสระไทยแตกในหลาย PDF และอ่านภาพสแกนไม่ได้)
- ตอนสอน (คำใบ้ แชต ประเมินคำอธิบาย) ส่งเอกสารของ Gem ทั้งหมดให้ AI ทุกครั้งเป็นความจำของ Gem: ไม่เกิน 100,000 ตัวอักษรส่งต้นฉบับเต็ม ยาวกว่านั้นใช้บันทึกที่ AI สรุปไว้ตอนสร้างคลังโจทย์ วางใน system prompt ส่วนที่คงที่ Gemini จึงแคชให้ ถ้า Gem ไม่มีเอกสารใช้การค้น BM25 แบบเดิม
- แชตจำบทสนทนาล่าสุด 12 ข้อความใน Gem เดียวกัน (เดิมไม่จำ) จึงต่อเนื่องและไม่ถามซ้ำ ไม่ปนแชตของบทเรียนอื่น

**Gem Version**
- บันทึกทุกครั้งเกิดเวอร์ชันใหม่ เก็บว่าใครแก้ แก้อะไร เมื่อไร และย้อนกลับได้
- แก้คำสั่งหรือ Knowledge File ระบบถามก่อนว่าจะสร้าง Item Bank ใหม่ไหม แก้แค่ชื่อหรือคำอธิบายใช้คลังเดิม
- Session ที่เริ่มแล้วใช้เวอร์ชันและคลังเดิมจนจบ

**นักเรียน**
- เห็น Gem เป็นการ์ด (ชื่อ คำอธิบาย ไอคอน) ทันทีที่บันทึก Flagged Item ไม่ถูกส่งให้นักเรียน

**Human-in-the-Loop**
- ครูตั้ง Alert Rule ต่อ Gem: เลือกสถานการณ์ ระดับ และโหมด "แจ้งอย่างเดียว" หรือ "หยุดรอครู" (AI ร่างคำตอบไว้รอครูอนุมัติ)
- สถานการณ์: ทำร้ายตนเอง (บังคับเปิดและหยุดรอครูเสมอ), Stagnation Deadlock, ไม่อยากเรียน, เครียด, Burnout, ปั๊มคำใบ้, ครบเพดานข้อ, นักเรียนขอคุยกับครู, AI ตอบไม่ได้หรือคำถามนอกบทเรียน, Misconception ใหม่, Guard บล็อกคำตอบ AI, Flagged Item
- แจ้งในเว็บเท่านั้น: ตัวเลขบนเมนู กล่องต้องดูตอนนี้ เสียง และ Browser Notification ไม่ส่งข้อมูลออกนอกเครื่อง

**AI Outage**
- แชตล้ม: ช่องแชตแสดง error แต่ทำโจทย์ต่อได้ · เกลาคำใบ้ล้ม: ใช้คำใบ้ต้นฉบับ
- สร้างโจทย์สดล้มและคลังหมด: หยุด Session ด้วยหน้า error ที่อ่านเข้าใจได้ ปุ่มลองอีกครั้ง ลองใหม่เองทุก 30 วินาที ไม่นับเวลาคิด
- ทุกกรณีแจ้งครูพร้อมข้อความ error

**Gem Flow: AI ออกแบบลำดับการสอนจากคำสั่งของครู** ([ADR-0004](adr/0004-ai-designs-each-gems-flow-from-the-teachers-prompt.md))
- ผังมาตรฐานเป็นแม่แบบอ้างอิงเท่านั้น (ปรับ 25 ต.ค. 2569): ไม่ใช้เป็น Flow ของ Gem ใด ไม่มีปุ่มเลือกใช้ และไม่ใช้แทนเมื่อ AI ออกแบบไม่ผ่าน (ครูกดออกแบบใหม่) Gem ที่ยังไม่มี Flow ที่ออกแบบจากคำสั่งไม่แสดงให้นักเรียน ครูเปิดดูแม่แบบอ้างอิงได้ในแท็บ Flow หัวข้อ 3–6 Stress Test และหน้ากฎยังอธิบายแม่แบบนี้
- ออกแบบตาม prompt ของครูทั้งหมด (ปรับ 25 ต.ค. 2569): ทุกขั้นและทุกเส้นมาจากคำสั่งของครูหรือเอกสารที่แนบ ไม่เติมขั้นจากแม่แบบมาตรฐาน (ข้อคู่ขนาน ทบทวนพื้นฐาน พัก รอครู) ถ้าครูไม่ได้สั่ง ทุกขั้นระบุที่มา (reason) และ AI ต้องเขียนรายการแนวทางของครูทีละข้อพร้อมขั้นที่ทำแนวทางนั้น ข้อไหนไม่มีขั้นรองรับ ตัวตรวจส่งกลับให้ AI แก้ (สูงสุด 3 รอบ) ครูเห็นรายการนี้ในแท็บ Flow กรณีที่ครูไม่ได้บอกใช้ทางที่เรียบง่ายที่สุดตามแนวทางของครู กลไกที่ล็อกไว้รองรับความปลอดภัยแทน ตัวอย่างรูปแบบใน prompt เป็นตัวอย่างสั้นที่ไม่ใช่แม่แบบมาตรฐาน เพื่อไม่ให้ AI ยึดโครงเดิม
- เงื่อนไขบนเส้นแยกทางตามรหัสข้อผิดพลาดได้ (`bug == "BUG-M01"`, `bug_type == "slip"`) และมีขั้น "กิจกรรมที่ AI สร้าง" สำหรับสิ่งที่คลังขั้นไม่มี AI สร้างเนื้อหาจากเป้าหมายที่บรรยายไว้ตอนนักเรียนมาถึง ผ่าน Answer-Leak Guard และประเมินคำตอบที่พิมพ์ได้
- ถ้าคำสั่งของครูกำหนดลำดับการสอน AI ออกแบบ Flow เป็นกราฟของขั้นอิสระ เพิ่มขั้นใหม่ได้: ทำโจทย์ (เลือกตาม Mastery, โจทย์หลักตามลำดับ, ง่ายลง, ยากขึ้น, ข้อคู่ขนาน, ทบทวนพื้นฐาน), คำใบ้ (ระดับ 1–3 หรืออัตโนมัติ หน่วงเวลาได้), บทเรียนย่อ, อธิบายความคิด, พัก, แจ้งครู, หยุดรอครู, ด่านตัดสินใจ และจบ ไม่กำหนดก็ใช้ผังมาตรฐาน (Standard Template)
- เส้นมีเงื่อนไขเป็นกฎที่ AI เขียนไว้บนตัวแปรของ Student Model (ตอบถูก/ผิด ครั้งที่ผิด ระดับคำใบ้ Misconception เวลาคิด Fuzzy Impasse Mastery ข้อที่ทำถูก ฯลฯ) engine ไล่เส้นตามลำดับ เส้นแรกที่เป็นจริงชนะ ไม่มีเส้นที่ตรงก็ใช้ทางเริ่มต้นของระบบ
- ใช้ LLM ตัดสินสดเฉพาะขั้น "อธิบายความคิด" ที่ครูสั่งให้ประเมินตามเกณฑ์ของครู ผลไม่แสดงให้นักเรียนเห็น บันทึกใน ai_logs และร่องรอยให้ครูตรวจ
- ตัวเลขมาจากคำสั่งของครูภายในช่วงที่ปลอดภัย (เช่น เพดานข้อ 5–40, หน่วงคำใบ้ 0–60 วินาที, พัก 15–300 วินาที) ค่าของ Admin เป็นค่าเริ่มต้น
- ล็อกไว้ทุก Flow: ตรวจถูกผิดด้วยกฎและไม่เฉลย · หยุดเมื่อมีข้อความทำร้ายตนเองและ Manual Override · กรองข้อมูลและจับเดาสุ่ม · Idle Pause และเพดานจำนวนข้อ (ผิดข้อเดียวกันครบ 6 ครั้งส่งต่อครู)
- ครูตรวจในแท็บ Flow ของ Gem: ผัง ขั้น เส้น เงื่อนไข (แปลเป็นภาษาคน) และตัวเลข แก้ได้ทุกอย่าง ทุกการแก้ตรวจที่ server ทันที บันทึกเป็น Gem Version กดให้ AI ออกแบบใหม่ หรือกลับไปใช้ผังมาตรฐานได้
- Stress Test สถานการณ์สาธิต และหน้ากฎ R-01–R-55 เก็บไว้สำหรับแม่แบบมาตรฐานเท่านั้น

**Admin**
- ผังของ Admin ไม่ตายตัว: Gem ที่มี Gem Flow วาดตามขั้นและเส้นที่ AI ออกแบบ จัดตำแหน่งอัตโนมัติ พร้อมแถบกลไกที่ล็อกไว้ใต้ผัง และชิปนักเรียนอยู่บนขั้นที่นักเรียนอยู่จริง ส่วน Gem ที่ใช้ผังมาตรฐาน: ทุกจุดที่แสดงผัง (หน้า Gem ที่ครูออกแบบ, หัวข้อ 3 ผังตรรกะสด, กิจกรรมสด) วาดเฉพาะผังของ Gem นั้น กล่องของเครื่องมือที่ครูปิดไม่อยู่ในผัง และเส้นต่อไปขั้นที่ engine ใช้จริง (เช่น ปิด Isomorphic Test แล้ว "ผิด" ไปด่าน 2 เลย, ปิดบันไดคำใบ้แล้วมีเส้นลองใหม่เอง, ปิดแชตแล้วกล่องที่เกิดจากแชตหายไป) ใต้ผังบอกว่าขั้นไหนไม่อยู่ในผังเพราะอะไร กระดิ่งบนกล่องที่ตั้งแจ้งเตือน มือบนกล่องที่หยุดรอครู
- ข้างผังแสดงสิ่งที่ครูออกแบบ: prompt 4 กรอบเต็ม, Knowledge File, Knowledge Map, สถิติ Item Bank และ Flagged Item, ประวัติ Gem Version
- ผังมีกล่องใหม่: สร้างโจทย์สด, AI ขัดข้อง, หยุดรอครูอนุมัติ
- ไทม์ไลน์รายนักเรียนรวมขั้นของนักเรียนกับการกระทำของครู: แจ้งเตือนเมื่อไร ครูเปิดดูหลังกี่นาที ตอบอะไร อนุมัติหรือแก้ร่างอย่างไร สั่ง Override อะไร และเรียนกับ Gem เวอร์ชันไหน
- หน้าตั้งค่าแสดง Gemini API key เป็นช่องหลัก Claude เป็นตัวสำรองพับไว้

## 1. ที่มาและสภาพปัญหา

- กลุ่มเป้าหมายตัวอย่างคือนักเรียน ม.2 เรื่องการแก้สมการเชิงเส้นตัวแปรเดียว ระบบรองรับวิชาอื่นที่ครูใส่เอง
- Pain Point และการจำแนกปัญหาใช้ตามสเปก ได้แก่ Static CAI, Cognitive Short-circuiting, Illusion of Competence, Learning Gap และภาระครู

## 2. สถาปัตยกรรม 4 แบบจำลอง

**Domain Model**
- Knowledge Map ของแต่ละ Gem: AI สร้าง Prerequisite 2–3 เรื่องเรียงจากพื้นฐานที่สุด → Target Concept ครูแก้ได้ในหน้าแก้คลังโจทย์
- Item หนึ่งข้อวัด Concept เดียว
- Answer Format ที่รองรับ: ปรนัย, ตัวเลข (เช่น 2.5 = 5/2) และข้อความสั้น ระบบแปลงเลขไทยและตัดช่องว่างให้อัตโนมัติ ส่วน Drag & Drop ไว้เฟส 2
- ทุก Concept ต้องมีโจทย์อย่างน้อย 2 Answer Format เพื่อให้ Cross-Format Check ทำงานได้

**Student Model**
- Digital Trace = [วัน-เวลา] + [Student Code] + [การกระทำ] + [วัตถุเป้าหมายบนหน้าจอ]
- ตัวแปรที่คำนวณ: Response Time, Error Count, First Attempt Success, Item Accuracy, Hint Abuse Index, Content Revisit และความยาว Session
- Response Time นับตั้งแต่ช่องตอบพร้อมใช้ ไม่รวมช่วงที่ถูกล็อก และตัดส่วนที่เกิน 5 นาทีทิ้ง
- Mastery คิดต่อ Concept จาก 5 ข้อล่าสุด น้ำหนักต่อข้อ: ถูกครั้งแรก 1.0 · แก้เองถูกระหว่าง Deliberate Delay 0.8 · หลัง L1 0.7 · หลัง L2 0.4 · หลัง L3 0.2 · ข้อที่มี Rapid Guess ไม่นับ

**Pedagogical Model**
- Learning Path: Mastery ≥ 0.8 และเร็วกว่าเวลาที่คาด → Fast-Track · 0.5–0.79 → Standard Flow · ต่ำกว่า 0.5 → Supported Flow
- Hint Ladder 3 ระดับ ไม่มีระดับใดบอกคำตอบสุดท้าย
- Deliberate Delay 15 วินาทีหลังผิดครั้งแรก ระหว่างนั้นนักเรียนลองตอบใหม่เองได้

**User Interface**
- พื้นที่คิดโจทย์และแผงคำใบ้อยู่หน้าจอเดียวกัน เพื่อลด Split-Attention
- Mastery Bar ไม่มีตัวเลขและไม่มีสีเตือน ลดลงได้แต่มาพร้อมข้อความเชิงบวกเสมอ Risk Score ไม่แสดงต่อนักเรียน
- หน้านักเรียนรองรับมือถือและแท็บเล็ต

## 3. ตรรกะและการไหลของข้อมูล

ผังเต็มอยู่ใน [flow.md](flow.md)

- **ก่อนเข้าด่าน:** ส่งซ้ำภายใน 1 วินาทีนับเป็นครั้งเดียว คำตอบผิดรูปแบบไม่นับเป็น Attempt และ Data Cleaning ตัดเวลาที่เกิน 5 นาที
- **ด่าน 1:** ตรวจถูกผิด ถ้าถูก อัปเดต Mastery แล้วเลือก Learning Path
- **ด่าน 2:** ผิดและเร็วกว่าเวลาอ่านขั้นต่ำ (ค่าเริ่มต้น 3 วินาที ตั้งต่อข้อได้) ถือเป็น Rapid Guess คะแนนข้อนั้นเป็นโมฆะ ไม่เพิ่ม Error Count และล็อกปุ่มตอบ 15 วินาที
- **วินิจฉัยก่อนด่าน 3:** เทียบกับ Bug Library เพื่อตั้ง Hint Floor
  - Misconception → เริ่มที่ L2 และบันทึกแท็กให้ครูเห็น
  - Slip (Mastery ≥ 0.5) → L1
  - Unclassified → เดินบันไดตามปกติ LLM เสนอแท็กได้ แต่ไม่มีผลจนกว่าครูจะยืนยัน
- **ด่าน 3 ตาม Error Count:** 1 → Deliberate Delay แล้ว L1 · 2 → L2 · 3 → Fuzzy Logic ดูว่าเวลาคิดยาวขึ้นต่อเนื่องหรือไม่ ถ้าใช่ → Impasse ถ้าไม่ → L3 · 4 ขึ้นไป → Impasse
- **Isomorphic Test:** ผ่านด้วยคำใบ้ระดับใดก็ตาม ข้อถัดไปเป็น Isomorphic Test ซึ่งปิดคำใบ้และตอบได้ 2 ครั้ง ถ้าไม่ผ่าน ข้อก่อนหน้าได้น้ำหนัก 0 และเปิดคำใบ้คืน ถ้าไม่ผ่าน 2 รอบติดกันใน Concept เดียว → Impasse
- **Remedial Loop:** ใช้ Prerequisite ที่ผูกกับ Misconception ที่พบ ถ้าไม่มีใช้ตัวที่ Mastery ต่ำที่สุด ผ่านเมื่อถูก 2 ข้อติดกัน แล้วกลับข้อเดิมโดย Error Count เริ่มนับใหม่ Concept ที่ไม่มี Prerequisite ใช้ Walkthrough Example + โจทย์ที่ง่ายลงแทน
- **Circuit Breaker และ Deadlock:** เกิด Impasse ซ้ำใน Remedial → Circuit Breaker พัก 1 นาที → Walkthrough → ปิดรอบนั้น ส่งซ่อมเสริมครบ 2 รอบแล้วยังติด → Stagnation Deadlock และแจ้งครู
- **จบชุด:** เมื่อ Mastery ของ Target Concept ≥ 0.8 (คิดจากอย่างน้อย 3 ข้อ) และทำ Main Item ครบหรือทำ Challenge Item ถูก 1 ข้อ ถ้าทำครบ 20 ข้อแล้วยังไม่ถึงเกณฑ์ ให้จบ Session โดยบันทึกความคืบหน้า และแจ้งครูแบบเงียบ
- **ปุ่มขอคำใบ้:** ก่อนลองตอบ ปลด L1 หลังคิด 30 วินาที ระดับใหม่ได้จากการลองตอบเท่านั้น กดซ้ำได้คำถามนำในระดับเดิม กด 3 ครั้งใน 10 วินาทีถือเป็น Hint Abuse ปุ่มพัก 10 วินาที ส่วนคำใบ้ตามบันไดขึ้นเองหลังตอบผิด
- **Flow Position:** engine เก็บตำแหน่งนักเรียนเป็น Flow Position และบันทึก Decision Trace ทุกครั้งที่ย้าย ([ADR-0002](adr/0002-named-flow-positions.md))

## 4. เครื่องมือและการบูรณาการ AI

- **Fuzzy Logic:** เขียนเองตามหลักในใบงานที่ 5 (Fuzzification, Rule Evaluation แบบ min/max, Defuzzification แบบ Center of Gravity) ทำงานทุกครั้งที่ตอบ ใช้ตัดสินแนวโน้มเวลาคิดตอนผิดครั้งที่ 3 เลือกความยากข้อถัดไป และคำนวณ Risk Score
- **K-Means:** ต่อยอดโค้ดในบทที่ 6 สไลด์ 11 ซึ่งคำนวณ Euclidean distance แล้วจัดเข้ากลุ่มที่ใกล้ที่สุดเพียงรอบเดียว เราเพิ่มขั้นปรับ centroid แล้ววนจนกลุ่มไม่เปลี่ยน
  - ใช้ 3 ฟีเจอร์ คือ เวลาคิดเฉลี่ย, สัดส่วนที่ตอบถูก และความยาว Session เฉลี่ย (ปรับสเกลก่อนคำนวณ)
  - k = 4 แล้วตั้งชื่อกลุ่มจากตำแหน่ง centroid ด้วยกฎที่เขียนไว้ชัด
  - ฟีเจอร์ที่ 3 ต้องมี เพราะกลุ่ม Bite-sized Users หมายถึงคนที่เรียนทีละช่วงสั้น ๆ ซึ่งเวลาคิดกับความถูกต้องวัดไม่ได้
- **MLP:** ไม่ทำในเฟสแรก
- **Reinforcement Learning:** ไม่ทำ แต่ใช้คำศัพท์ในบทที่ 6 อธิบายวงจรของระบบใน Principle Card
  - Agent = engine
  - Environment = นักเรียน หรือ Simulated Cohort
  - State = Student Model + Flow Position
  - Action = เลือกโจทย์หรือคำใบ้
  - Reward = ผ่านข้อ (+) หรือออกจากระบบ (−)
- **AI Tutor:** Authored Hint เป็นข้อมูลหลัก LLM แค่ปรับถ้อยคำ ทุกข้อความต้องผ่าน Answer-Leak Guard และ LLM ไม่ตัดสินถูกผิด ([ADR-0001](adr/0001-authored-hints-and-answer-leak-guard.md))
- **prompt 4 กรอบ:** Role & Persona, Context & Environment (เติมตัวแปรจาก Student Model), Task & Intent (ระดับคำใบ้) และ Constraints & Fallback
- **Provider:** เลือก Claude, Gemini หรือ Offline ในหน้า Admin มีลำดับสำรองเมื่อตัวที่เลือกใช้ไม่ได้ ค่าเริ่มต้นฝั่ง Claude คือ `claude-opus-5-5` (เปลี่ยนเป็นโมเดลที่ถูกกว่า เช่น `claude-haiku-5-5` ได้ในหน้าตั้งค่า) ส่วนชื่อโมเดล Gemini ให้กด "ทดสอบการเชื่อมต่อ" แล้วเลือกจากรายการที่ key นั้นใช้ได้
- **RAG:** ดึงรายการ Bug Library ตามแท็ก และย่อหน้าจากเอกสารวิชา (PDF ที่มีตัวอักษร, DOCX, TXT, MD) ค้นด้วย BM25 + ตัดคำไทยด้วย PyThaiNLP ในเครื่อง ยังไม่รองรับ PDF สแกน
- ตัดข้อมูลส่วนตัวออกจากแชตก่อนส่งให้ Provider และตรวจ Distress Message ในเครื่องก่อนเสมอ
- นับโทเคนทุกครั้งที่เรียก Provider ใช้เป็นหลักฐานว่าภาษาไทยใช้โทเคนมากกว่า

## 5. สาธิตต้นแบบ

- Simulated Cohort 30–40 คน สร้างจาก persona ของแต่ละ Student Cluster และติดป้ายข้อมูลจำลองเสมอ ไม่เรียก Provider และการแจ้งเตือนของนักเรียนจำลองไม่ขึ้นในหน้าครู
- Demo Mode ย่อเวลาของกลไกต่าง ๆ เช่น 5 นาทีเหลือ 10 วินาที
- เล่น 3 สถานการณ์จากแท็บ 5 ของหน้า Admin: ตอบถูกและเร็ว · ตอบผิด (Slip และ Misconception) · Impasse
- ตอนสาธิตให้วางหน้านักเรียนคู่กับหน้า Admin แล้วผังจะขยับตามทุกครั้งที่ตอบ

## 6. Edge Case และ Stress Test

ทุกกรณีในตารางมีปุ่มยิงทดสอบในแท็บ 6 ของหน้า Admin

| เหตุการณ์ | ระบบทำอะไร |
|---|---|
| หน้าจอนิ่งเกิน 5 นาที | Idle Pause พร้อมข้อความปลอบใจ ตัดเวลาส่วนเกินออกจากสถิติ Error Count ไม่เปลี่ยน |
| เว็บกระตุกจนกดส่งรัว | รวมเป็นการส่งครั้งเดียว |
| เน็ตหลุดกลางคัน | เก็บสถานะทุกครั้งที่ส่ง กลับมาทำต่อจากจุดเดิม ไม่บันทึกคะแนนเป็นศูนย์ |
| คำตอบผิดรูปแบบ เช่น พิมพ์ตัวอักษรในข้อตัวเลข | บอกให้แก้รูปแบบ ไม่นับเป็น Attempt แต่บันทึกเป็น Digital Trace |
| จอสัมผัสรวน กดพลาด | "ยกเลิกคำตอบล่าสุด" ภายใน 10 วินาที ข้อละครั้ง ไม่นับใน Error Count และปลดล็อก Rapid Guess · "เริ่มข้อนี้ใหม่" ล้างคำตอบและเวลา แต่ Error Count คงเดิม |
| พิมพ์หลอกขอเฉลย หรือพิมพ์นอกเรื่อง | AI Tutor ตอบเป็นคำถามนำและดึงกลับเข้าโจทย์ Answer-Leak Guard ตรวจซ้ำอีกชั้น |
| ปรนัยได้เต็มแต่เติมคำทำไม่ได้ | Cross-Format Check ลด Mastery ของ Concept นั้น |
| ครูกด Manual Override | มีผลทันทีเหนือกฎอัตโนมัติ และบันทึกลง audit log |

## 7. การควบคุมโดยมนุษย์ จริยธรรม และความเป็นส่วนตัว

| สัญญาณ | ฝั่งนักเรียน | Teacher Alert |
|---|---|---|
| Stagnation Deadlock | หยุดลูป รอครู | ปกติ |
| ข้อความเครียดหรือท้อ | Circuit Breaker | ปกติ |
| ข้อความ "ไม่อยากเรียนแล้ว" | ให้เลือก พักก่อน · ทำต่อแบบง่ายลง · หยุดวันนี้ และบันทึกความคืบหน้าไว้ | ปกติ |
| ข้อความที่สื่อถึงการทำร้ายตนเอง | หยุดทันที แสดงสายด่วนสุขภาพจิต 1323 | ด่วน |
| Burnout Signal: Risk Score เกินเกณฑ์, Idle Pause 3 ครั้งใน Session, Rapid Guess ติดกัน 3 ครั้ง | ไม่หยุด ไม่มีข้อความพิเศษ | เงียบ |

- Manual Override มีผลเหนือกฎอัตโนมัติทุกอย่าง และบันทึกเป็น audit log
- บันทึกทุก prompt และคำตอบของ AI ให้ครูตรวจย้อนหลังได้
- PDPA: ใช้ Student Code แทนชื่อทุกที่ Roster เก็บแยกและเปิดได้แค่ครู Admin เห็นแค่รหัส ไม่ส่งข้อมูลนักเรียนไปเทรนโมเดล (เช็กเงื่อนไขล่าสุดของ Gemini แบบฟรี ซึ่งอาจนำข้อมูลไปปรับปรุงผลิตภัณฑ์)
- Anti-Labeling: Risk Score และ Student Cluster ไม่แสดงต่อนักเรียน Burnout Signal แจ้งครูแบบเงียบโดยไม่หยุดกิจกรรม

## ค่าตัวเลขทั้งหมด

Admin ปรับได้ทุกค่า และ Demo Mode ย่อเวลาให้ได้

| กลไก | ค่า |
|---|---|
| Deliberate Delay | 15 วินาที หลังผิดครั้งแรก |
| Rapid Guess | ผิดและเร็วกว่า 3 วินาที → ล็อก 15 วินาที |
| Hint Abuse | กด 3 ครั้งใน 10 วินาที → ปุ่มพัก 10 วินาที |
| ปุ่มคำใบ้ก่อนลองตอบ | ปลดหลังคิด 30 วินาที |
| Hint Floor | Misconception → L2 · Slip (Mastery ≥ 0.5) → L1 |
| Idle Pause | ไม่มีการกระทำ 5 นาที |
| หน้าต่าง Mastery | 5 ข้อล่าสุดต่อ Concept |
| น้ำหนักต่อข้อ | 1.0 · 0.8 · 0.7 · 0.4 · 0.2 (ดูหัวข้อ 2) |
| เกณฑ์ Learning Path | ≥ 0.8 Fast-Track · 0.5–0.79 Standard · ต่ำกว่า 0.5 Supported |
| Isomorphic Test | ตอบได้ 2 ครั้ง ไม่มีคำใบ้ |
| Remedial Loop | ผ่านเมื่อถูก 2 ข้อติดกัน · สูงสุด 2 รอบต่อข้อ |
| Circuit Breaker | พัก 1 นาที แล้ว Walkthrough Example |
| ยกเลิกคำตอบ | ภายใน 10 วินาที ข้อละ 1 ครั้ง |
| Burnout Signal | Idle Pause 3 ครั้งต่อ Session · Rapid Guess ติดกัน 3 ครั้ง · Risk Score ≥ 70 (เมื่อตอบแล้วอย่างน้อย 5 ครั้ง) |
| ส่งซ้ำ | ภายใน 1 วินาทีนับเป็นครั้งเดียว |

## ข้อจำกัดที่ควรพูดตรง ๆ ในการนำเสนอ

- Simulated Cohort สร้างจาก persona ที่เรากำหนดเอง K-Means จึงเจอกลุ่มเหล่านั้นได้ง่าย ต้องใช้ข้อมูลนักเรียนจริงจึงจะพิสูจน์ได้
- Answer-Leak Guard ตรวจคำตอบในรูปแบบที่รู้จัก ไม่ได้เข้าใจความหมายทั้งหมด
- RAG ค้นด้วยคำ (BM25) ไม่ใช่ความหมาย และยังอ่าน PDF สแกนไม่ได้
- เกณฑ์ตัวเลขทั้งหมดเป็นค่าตั้งต้นจากสเปก ยังไม่ได้ปรับจากข้อมูลจริง
