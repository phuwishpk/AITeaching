# AI ออกแบบ Flow ของ Gem จากคำสั่งของครู แต่ engine รันตามกฎบนเส้นที่ตรวจแล้ว

ผังตรรกะของ Gem ไม่ตายตัวอีกต่อไป เมื่อครูเขียนลำดับการสอนในคำสั่งของ Gem (เช่น "ผิดครั้งที่สองให้อ่านบทเรียนย่อก่อน" หรือ "ทุกข้อที่ถูกด้วยคำใบ้ให้อธิบายวิธีคิด") LLM ออกแบบ Gem Flow เป็นกราฟของขั้นจากคลังขั้นที่ engine รันได้ (ทำโจทย์ คำใบ้ บทเรียนย่อ อธิบายความคิด พัก แจ้งครู หยุดรอครู ด่านตัดสินใจ จบ) เส้นระหว่างขั้นมีเงื่อนไขเป็นนิพจน์อ่านได้บนตัวแปรของ Student Model เช่น `wrong and error_count >= 2` engine ไล่เส้นตามลำดับ เส้นแรกที่เป็นจริงชนะ ตัวเลขในคำสั่งของครูใช้ได้แต่ถูกตัดให้อยู่ในช่วงที่ปลอดภัย ค่าของ Admin เป็นค่าเริ่มต้น ครูตรวจและแก้ได้ทุกขั้นในแท็บ Flow ถ้าคำสั่งไม่ได้กำหนดลำดับการสอน Gem ใช้ผังมาตรฐาน เดิม

เราเลือกแบบนี้เพราะผู้ใช้ต้องการให้ "flow เป็นไปตามที่ครู prompt ออกแบบ" โดย ADR-0001 และ ADR-0003 ยังจริงอยู่ คือ LLM ออกแบบได้ แต่ทุกการตัดสินระหว่างเรียนยังเป็นกฎที่อธิบายได้ Decision Trace จึงบอกได้ทุกครั้งว่าผ่านเส้นไหนเพราะเงื่อนไขอะไร

## สิ่งที่ล็อกไว้ทุก Flow (อยู่นอกกราฟ ครูและ AI แก้ไม่ได้)

- ตรวจถูกผิดด้วยกฎจาก Answer Key และ Answer-Leak Guard (รวมข้อความของบทเรียนย่อ และ Walkthrough ที่เฉลยโจทย์ที่นักเรียนยังทำไม่ได้)
- ข้อความทำร้ายตนเองหยุดทันที และ Manual Override ของครู
- Data Cleaning (ส่งซ้ำ คำตอบผิดรูปแบบ ตัดเวลาคิดส่วนเกิน) และ Rapid Guess
- Idle Pause เพดานจำนวนข้อ และผิดข้อเดียวกันครบ 6 ครั้งส่งต่อครู (กัน Flow ที่ไม่มีทางออก)

## Considered Options

- เลือกจากแม่แบบ Flow สำเร็จรูปไม่กี่แบบ: ปลอดภัยและทดสอบง่าย แต่ไม่ได้ทำตามคำสั่งของครูจริง
- ปรับเฉพาะตัวเลขของผังมาตรฐาน จากคำสั่ง: ผังยังตายตัว ซึ่งผู้ใช้บอกว่าไม่ต้องการ
- ให้ LLM ตัดสินทุกเส้นสดระหว่างเรียน: ยืดหยุ่นที่สุด แต่ช้า ผันผวน และอธิบายไม่ได้ ใช้ได้เฉพาะขั้นอธิบายความคิดที่ครูสั่งให้ประเมิน และบันทึกทุกครั้ง

## Consequences

- Stress Test (หัวข้อ 6) สถานการณ์สาธิต (หัวข้อ 5) และหน้ากฎ R-01–R-55 อธิบาย ผังมาตรฐาน จึงรันบนแม่แบบมาตรฐานเสมอ แม้ Gem ที่ใช้สาธิตจะมี Flow ของตัวเอง
- ทุก Flow ต้องผ่านตัวตรวจก่อนบันทึก: ขั้นแรกเป็นขั้นทำโจทย์ ทุกขั้นมีทางออก ไปถึงขั้นจบได้ ไม่มีวงที่วนโดยไม่หยุดรอนักเรียน และเงื่อนไขใช้แค่ตัวแปรที่รู้จัก ถ้า LLM แก้สองรอบแล้วยังไม่ผ่านใช้ผังมาตรฐาน
- Flow ใช้กับนักเรียนทันทีเหมือนคลังโจทย์ แต่ขึ้นป้าย "ยังไม่ได้ตรวจ" จนครูยืนยัน Flow ที่ครูแก้เองไม่ถูกออกแบบทับตอนสร้างคลังใหม่
- ผังของ Admin สำหรับ Gem ที่มี Flow ของตัวเองจัดตำแหน่งอัตโนมัติ (dagre) และมีแถบกลไกที่ล็อกไว้ใต้ผัง
- Walkthrough ของผังมาตรฐาน ยังไม่ผ่าน Answer-Leak Guard แบบเดียวกับบทเรียนย่อ (ข้อจำกัดเดิมที่ยังไม่แก้)
