# Flow Position เป็นสถานะที่มีชื่อ และผังหน้า Admin สร้างจากนิยามเดียวกับ engine

engine เก็บตำแหน่งของนักเรียนแต่ละคนเป็น Flow Position ค่าเดียวที่มีชื่อ เช่น Deliberate Delay หรือ Remedial Loop รอบ 1 แทนการกระจายสถานะไว้ในตัวแปรหลายตัว ผังในหน้า Admin วาดจากนิยามตำแหน่งและเส้นทางชุดเดียวกับที่ engine ใช้ และทุกการย้ายตำแหน่งบันทึก Decision Trace ส่วนกฎ 3 ด่านยังเขียนเป็น If-Else ซ้อนกันในฟังก์ชันเดียว ให้ตรงกับสไลด์หัวข้อ 3.1 เราเลือกแบบนี้เพราะหน้า Admin ต้องบอกได้ตลอดเวลาว่านักเรียนแต่ละคนอยู่ตรงไหนและเพราะอะไร และผังที่วาดแยกจากโค้ดจะค่อย ๆ เพี้ยนไปจากของจริง

## Considered Options

- เขียนเป็น If-Else ล้วน แล้วคำนวณตำแหน่งย้อนจากตัวแปร: ทุกครั้งที่เพิ่มกฎต้องแก้ตรรกะเดาตำแหน่งตาม และต้องดูแลผังกับโค้ดแยกกัน

## ปรับ 29 ต.ค. 2569: ทุกการขยับขึ้นในผังของ Gem

ผังของ Gem ต้องเห็นนักเรียนทุกขั้น รวมตอนคุยกับ AI และตอนพัก engine จึงเก็บ "กล่องในผัง" แยกจาก Flow Position และทุก Decision Trace บันทึก `map_path` คือกล่องเดิม ขั้นที่ผ่าน (รวมขั้นที่ผ่านไปทันที เช่น คำใบ้ที่ไม่หน่วง) และกล่องที่ไปอยู่ หน้า Admin วาดเส้นทางทั้ง Session จาก `map_path` พร้อมเลขลำดับ การขยับที่ไม่มีเส้นในผังวาดเป็นเส้นโค้งระหว่างกล่อง

- ส่งข้อความแชต ชิปย้ายไปกล่อง "แชตกับ AI" และขึ้นว่ากำลังคิดจน AI ตอบ อยู่ที่นั่นจนกลับมาทำบนจอหลัก (ส่งคำตอบ กดคำใบ้ อ่านจบ ฯลฯ) หรือระบบย้ายตำแหน่ง Flow Position ไม่เปลี่ยน นักเรียนจึงยังตอบโจทย์ได้ และกฎ 3 ด่านไม่ต้องรู้จักแชต การเข้าและออกกล่องแชตบันทึกเป็น Decision Trace ที่ตำแหน่งต้นและปลายเท่ากัน
- กลไกที่ล็อกไว้เป็นแถวกล่องในผัง (ไม่ใช่ปุ่มนอกผัง) ชิปจึงอยู่ในกล่องและเส้นทางลากถึงได้ ถ้าครูกำหนดทางหลังพักเพราะเครียด (`after_stress`) กล่องพักเพราะเครียดเป็นกล่องเต็มในผังพร้อมเส้น แชต → พัก → ขั้นที่ครูกำหนด
- ข้อมูลเก่าที่ไม่มี `map_path` ยังแสดงตำแหน่งได้ แต่ไม่มีเส้นทาง
